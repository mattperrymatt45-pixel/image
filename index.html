    Step 4 · Transparency

    How the score is computed

    There is no hidden model. You can reproduce every number by hand using the rules below.

    1 Parse the prompt

    Lowercase the text, remove punctuation, split into words, drop stop words (a, the, in, on…), then look each remaining word up in a small public lexicon that maps synonyms to one of three categories: object, attribute or scene. Example: puppy → object:dog.

    2 Compare with image labels

    Each bundled image has a fixed, human-written concept list in the same three categories. For every category present in the prompt we compute recall = matched concepts ÷ requested concepts. No image embeddings or similarity networks are used.

    3 Weight and normalise

    Weights: object 45, attribute 30, scene 25. If a category is absent from the prompt, its weight is redistributed over the active categories so a short prompt can still reach 100:

    score = round( Σ ( wc × recallc ) / Σ wc × 100 )

    4 Report confidence

    Vocabulary coverage = recognised words ÷ meaningful words. It is shown separately and does not alter the score. If nothing is recognised, a clearly labelled fallback uses literal word overlap with the caption and caps the score at 40.

    Verdict bands & known lexicon

    75–100 Strong match 50–74 Partial match 25–49 Weak match 0–24 No meaningful match

    The lexicon is deliberately small and visible in the page source (CONCEPT_GROUPS). Words outside it are listed as unrecognised in the dashboard rather than guessed at.

    Step 5 · Write-up

    Experiment report

    A ready-to-study lab record. The “Results” card updates automatically whenever you evaluate a prompt.

    A Aim

    To study how a text prompt can be used to interact with a set of images, and to build an explainable evaluation pipeline that ranks images by semantic relevance to that prompt — while making clear that a rule-based proxy is not equivalent to real multimodal model inference.

    T Theory

    Text-to-image systems learn a shared representation of language and vision; a prompt is encoded as text features and guides an iterative denoising process that synthesises pixels. Evaluation normally needs either human judges or a learned similarity model such as CLIP, which embeds image and text in a common vector space and compares them with cosine similarity.

    This lab does not implement either. It replaces the learned encoder with a transparent symbolic approximation: a controlled vocabulary of concepts attached to fixed images. The exercise isolates the evaluation idea — measuring prompt–image agreement — from the expensive generation and embedding steps.

    Al Algorithm

    INPUT : prompt P, images I[1..8] with concept sets C
OUTPUT: ranked list of (image, score, breakdown)

1. W ← {object:45, attribute:30, scene:25}
2. tokens ← normalise(P) \ stopwords
3. Q ← {}                      // requested concepts
4. for t in tokens:
5.     if t in LEXICON: Q[category] += canonical(t)
6.     else: unrecognised += t
7. if Q is empty: use literal-overlap fallback (cap 40)
8. A ← categories in Q with at least one concept
9. total ← Σ W[c] for c in A
10. for each image i:
11.     for c in A:
12.         recall ← |Q[c] ∩ C_i[c]| / |Q[c]|
13.         points[c] ← W[c] * recall / total * 100
14.     score_i ← round( Σ points )
15. sort images by score_i descending
16. return scores, points, matched/missing, coverage

    M Methodology

    1. Eight fixed SVG demonstration images were authored and manually labelled with object, attribute and scene concepts.
    2. Eight preset prompts were written so each has one clearly corresponding image.
    3. A fixed stop-word list and synonym lexicon normalise arbitrary user text.
    4. The weighted-recall rule is applied to all eight images; results are ranked and rendered in the gallery, comparison table, chart and dashboard.
    5. Observations and a conclusion are generated from the numeric results deterministically.
    6. The complete result set can be exported to CSV for external analysis (Excel, Sheets, pandas).

    Tools: one HTML file, inline CSS, vanilla JavaScript, embedded data:image/svg+xml images, and the browser's Blob API. No libraries, servers, keys or network calls.

    R Results (live)

    L Limitations

    • No real generation. Images are static, hand-drawn SVG placeholders; the prompt never changes them.
    • No CLIP / neural inference. Scores reflect keyword overlap with human labels, not learned visual–semantic similarity.
    • Vocabulary bound. Words outside the small lexicon are unrecognised; paraphrases and rare terms can fail.
    • Bag of words. Word order, negation (“no dog”), counting, spatial relations and composition are ignored.
    • Label bias. The concept lists were written by hand, so the metric inherits their omissions and mistakes.
    • Weight choice. 45/30/25 is an illustrative design decision, not an empirically validated weighting.
    • No visual realism assessment. Artefacts, aesthetics, diversity and safety are outside the score.
    • Tiny dataset. Eight images cannot support statistical generalisation about model quality.
    Step 6 · Usage

    How to run this experiment

    1. Save this page as index.html (it is already a single, complete file).
    2. Double-click the file, or drag it into any modern browser (Chrome, Edge, Firefox, Safari). No server, Python, Node.js, API key or installation is needed.
    3. Pick a preset prompt or type your own, then click ⚡ Evaluate prompt.
    4. Add images to the comparison with the card buttons, inspect the “Why this score?” breakdown, and read the dashboard.
    5. Click ⬇ Export results as CSV to download the full scored dataset, or 🖨 Print / Save PDF for a lab record.
    6. Use 🌙 Dark mode and ↺ Reset at any time; everything still works offline.

    Everything runs in your browser tab. The page makes zero external requests and stores nothing except your theme preference.
